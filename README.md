# ЭДО Помощник

Расшифровка подписи E-IMZO, обновление статуса в GoodSign, проверка и исправление Excel-шаблонов, поиск дублей маркировки.

Одна HTML-страница, которая показывает, что внутри подписи E-IMZO (PKCS#7 / CMS SignedData):
кто подписал, когда, каким сертификатом, и сам подписанный документ в виде JSON.

## Как пользоваться

1. Откройте страницу (ссылка на GitHub Pages — в описании репозитория) или скачайте `index.html` и откройте в браузере.
2. В DevTools → вкладка **Network** нажмите «Подписать».
3. Выберите запрос `sign` → вкладка **Payload**, скопируйте подпись (base64).
4. Вставьте её в поле — расшифровка появится сразу.

Можно вставить подпись с кавычками, целый JSON запроса или открыть файл `.p7s` / `.txt`.

## Что показывает

- Подписант: ФИО, должность, организация, ИНН, ПИНФЛ
- Время подписи и метка времени (TSA), если есть
- Сертификат: срок действия, серийный номер, кем выдан
- Проверки: действовал ли сертификат в момент подписи, совпадает ли ИНН со стороной документа, совпадает ли подписант с директором
- Документ: тип (счёт-фактура, ТТН, акт, договор, доверенность), номер, дата, сумма и полное JSON-дерево с поиском

## Обновление статуса документа в GoodSign

Если статус документа в общем списке GoodSign устарел, вставьте ID документа (32 символа, по одному на строку)
в поле «Обновить статус документа в GoodSign» и нажмите «Обновить статус». По каждому ID будет видно, обновился ли статус.
Если браузер не пустит запрос, рядом с ID появится ссылка — по ней статус обновится в новой вкладке.

## Проверка Excel-шаблонов

Загрузите заполненный шаблон Didox (.xlsx) в блок «Проверка Excel-шаблона» или перетащите его туда.
Тип шаблона определяется по строке с номерами столбцов: Счёт-фактура, ТТН, Гибридная ЭСФ, Произвольный документ.
Шаблон для загрузки ИКПУ (ИКПУ код + тип происхождения) тоже проверяется, включая повторы ИКПУ.

По каждой ошибке видно строку, столбец, поле, причину и значение. Проверяется:

- обязательные поля, в том числе по звёздочке (*) в заголовке шаблона
- ИНН (9 цифр) и ПИНФЛ (14 цифр), ИКПУ (17 цифр), коды и ID — только цифры, без пробелов
- допустимые ID: тип СФ, тип односторонней СФ, тип перевозки, подтип документа, области, происхождение товара и т.д.
- даты — текстом ДД.ММ.ГГГГ, а не в формате даты Excel
- порядковые номера документов, грузов и товаров
- цена (не больше 2 знаков после запятой для СФ, 5 — для ТТН и гибридной), ставка НДС (Без НДС / 0 / 12)
- суммы: количество × цена, НДС 12%, стоимость с НДС, нетто не больше брутто
- маркировка: если заполнено одно из полей, нужны все три; коды через пробел; длина кода от 18 до 63 символов;
  не больше 5000 кодов в одном документе; кириллица в коде; число кодов KIZ и количество;
  **дубли кодов** — в одной ячейке и по всему файлу

Отчёт можно скопировать целиком. Существование ИНН, ID районов и соответствие ИКПУ единице измерения проверяет Didox при загрузке.

### Исправленный шаблон

Если часть ошибок можно исправить без догадок, появляется кнопка «Скачать исправленный шаблон». Исправляется:

- пробелы в ИНН, ПИНФЛ, ИКПУ, ID и кодах, а также в начале и конце текстовых полей
- ИКПУ, у которого Excel потерял ведущий 0; ИНН, ПИНФЛ и ИКПУ, записанные числом, — в текст
- даты в формате даты Excel или вида 2025-07-01 — в текст ДД.ММ.ГГГГ
- ставка НДС «12%» → 12, «без ндс» → «Без НДС»; сумма НДС 0 при ставке «Без НДС» или 0
- «Стоимость с НДС» пересчитывается как стоимость поставки + НДС
- цена округляется до допустимого числа знаков
- если «количество × цена» не сходится со стоимостью поставки только потому, что цену округлили до копеек,
  цена уточняется: (стоимость − акциз) / количество, до 5 знаков для ТТН и гибридной ЭСФ (в СФ с 2 знаками это не всегда возможно — тогда только подсказка)
- коды маркировки — через один пробел, без повторов внутри ячейки; KIZ/NomUpak/IdentTransUpak — как в инструкции

Пустые обязательные поля, неверные ИНН, дубли кодов между строками и несходящиеся «количество × цена» не исправляются — их нужно поправить вручную.
В скачанной копии сохраняется оформление шаблона, исправленные ячейки подсвечены зелёным, а на листе «Исправления» указано, что было и что стало.

## Поиск дублей маркировки

Отдельный блок для любого списка кодов маркировки: вставьте коды (по одному на строку или через пробел)
или откройте Excel, CSV или TXT. Страница покажет, какие коды повторяются и где — номер строки или ячейка `Лист!B5`.

- В Excel кодом считается значение от 18 символов латиницей, цифрами и знаками, поэтому ИКПУ, ИНН и ПИНФЛ из соседних столбцов не мешают
- Коды делятся только пробелами и переводами строк — запятая и «;» внутри кода GS1 допустимы
- Скрытый разделитель GS не учитывается: код, отсканированный с ним и без него, считается одним кодом
- Коды короче 18 или длиннее 63 символов показываются отдельно как неверные
- Отдельно показываются пары «короткий код — начало длинного» (обычно один код с криптохвостом и без)
- Можно скопировать список дублей или весь список без дублей, а также скачать его в .txt

## Дизайн

В блоке «Оформление» можно выбрать один из пяти дизайнов. Выбор запоминается в браузере каждого пользователя.

- **Классика** — красный цвет, фон с сетью узлов и росчерками подписи
- **Didox** — фиолетово-синий цвет, на фоне всплывают документы и по пути получают подпись
- **Дождь** — сине-серый цвет, косой дождь со всплесками, ветер следует за мышью, изредка далёкая молния
- **Облака** — голубой цвет, живое небо с облаками и солнцем (Vanta.js и three.js загружаются только при выборе этого дизайна); в тёмной теме — ночное небо
- **Графит** — спокойный серый цвет, на фоне только символы base64

Жёлтые акценты остаются во всех дизайнах. Анимацию фона можно выключить.

## Безопасность

Расшифровка идёт только в браузере, подпись никуда не отправляется. Сервер не нужен.
Для обновления статуса в GoodSign отправляются только ID документов.
Excel-шаблон проверяется и исправляется в браузере и никуда не отправляется (библиотеки SheetJS и JSZip загружаются с cdnjs, three.js — с cdnjs, Vanta.js — с jsDelivr).

Файл читается в фоновом потоке браузера, поэтому страница не замирает на больших шаблонах. Пустые строки, до которых растянуто оформление шаблона, не перебираются.
Вся обработка идёт на устройстве пользователя, поэтому несколько человек, проверяющих файлы одновременно, друг другу не мешают.

Криптографическая подлинность подписи (O‘z DSt 1092) **не проверяется** — для этого нужен E-IMZO.
